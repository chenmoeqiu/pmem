# pmem —— 一个禁止向量检索的本地记忆库

**它不试图"更懂你"，它只保证：没有指名的东西，不会被唤醒。**

对话原文存在本地 SQLite 里，带时间戳、带精度、只追加。检索靠**标签**和**原文精确匹配**，
不用语义相似度。每条结论都能点回原话。

> 你是 AI、要改这个仓库的代码？直接读 [`docs/AGENTS.md`](docs/AGENTS.md)——里面有规矩、
> 代码地图、验收方式和踩过的坑。这份 README 是给使用者看的。

```bat
python tools/load_samples.py          :: 造一个 20 场对话的样例库
run.cmd --db data/sample.db search 咖啡
```

---

## 它解决什么问题

主流 RAG 记忆方案会把"旅行"关联到"摄影"，再把"摄影"关联到你提过的相机，
最后在你规划徒步路线时热情地建议你**带上那台 ZV-E10 和一杯威士忌**——
它没有时间轴，也没有常识边界，只有向量距离。

一次真实的失败：作者让 AI 帮忙规划一次徒步，它建议"带上你那台 ZV-E10"和"晚上喝一杯威士忌"。
作者并没有买那台相机，而徒步也不该背玻璃瓶。

问题不是它不懂作者，是它把"旅行 = 放松 = 威士忌"在向量空间里缝了起来：
"风景"离"摄影"近，"摄影"离"相机"近，"旅行"离"放松"近，"放松"离"酒"近。
每一跳都合理，整条链是假的。

**本项目的选择是：牺牲召回率，换精确与可追溯。**

| | 向量检索（RAG） | 本项目 |
|---|---|---|
| 召回依据 | 语义相近 | 标签 + 字面精确匹配 |
| 时间 | 通常没有 | 每条消息带时间戳与精度 |
| 状态判断 | 弱（"准备买"和"已清仓"距离极近） | 强（靠时间线判断先后） |
| 数据形态 | 浮点数，人不可读 | 纯文本 SQLite，随时可迁移 |
| 幻觉来源 | 召回到"语义相关但事实上无关"的东西 | 检索不到就明说找不到 |

## 五分钟跑通

需要 **Python 3.11+**，零第三方依赖。

```bat
:: 1. 建库（空库也能跑，只是没什么可看的）
run.cmd init

:: 2. 载入合成样例：20 场对话 / 56 条消息 / 2 张图 / 13 个标签 / 1 条待裁决
python tools/load_samples.py

:: 3. 看它有什么
run.cmd --db data/sample.db stats

:: 4. 两条检索路径
run.cmd --db data/sample.db search 咖啡        :: 全文兜底（字面命中）
run.cmd --db data/sample.db search --tag 咖啡  :: 标签主路径（换个说法也能到）

:: 5. 走完整链路问一次（需要 API key；没有就走离线模式）
run.cmd --db data/sample.db ask "上周手冲咖啡那次，我最后定的参数是什么"

:: 6. 验收：96 项行为断言
python tools/run_all.py
```

样例数据全部虚构：地名用"甲省/乙市"，人物只有"某教授"。没有真人、真公司、真行程。

### 接自己的数据

```bat
run.cmd import takeout D:\path\to\takeout-xxx.zip --dry-run   :: 先看清单，不写库
run.cmd import takeout D:\path\to\takeout-xxx.zip
run.cmd stats
```

## 它是怎么工作的

```
导入（Takeout / Voyager / note 实时写入）
        ↓
原文层：只追加 + 消息时间戳 + 附件 sha256 内容寻址
        ↓
打标：话题段 + 六个固定维度的标签（值只能从审核过的词表里选，没审核的进待审队列）
        ↓
┌──────────── 检索 ────────────┐
标签（主路径）        原文 FTS（兜底：型号/编号/人名）
└────────────┬────────────────┘
             ↓
路由（四支 + 第三档复核）→ 证据门（够不够）→ 生成
             ↓
热记忆（当前「清醒段」整段注入）／冷记忆（其余，可检索）
             ↑
     两个出口一个入口：context / note
```

几个不太一样的决定：

- **禁向量不是配置项**，是结构性的：代码里没有向量这条路径。
- **时间戳只能由存储层盖章**；精度分四档，`unknown` 的时间必须是 `NULL`——宁可没有，也不假装有。
- **热记忆按"睡了一觉"切分**：间隔 ≥ 6 小时 **且** 与睡眠窗口重叠 ≥ 2 小时。不是"跨自然日"（熬夜会把昨天带进今天）。
- **注入边界 = 排除边界**：热窗注入和冷检索排除读同一个值，否则会出现"既没注入又查不到"的黑洞。
- **证据门用代码强制**：模型声称"证据充足"却指不出任何一条，代码直接判不足。
- **转冷之后自动整理**：睡过一觉，上一段会话自己入队、自己切段打标（一次最多 2 场，两次间隔 ≥ 6 小时）。
- **机器产出必须能被人改**：待裁决是 `propose`（只写建议）→ `apply`（你确认才执行 + 写审计）。

## 它不做什么

这份列表比功能列表更重要——它决定了这个项目**不像**什么：

- **不做向量检索**，也不做"标签 + 向量"的混合召回。不是暂时不用，是禁止。
  （你见过的那种"语义相近就召回"的记忆插件，代价是：它会把"准备买"和"已经退了"当成同一件事。）
- **不用摘要替代原文**。记忆不是"一句话总结"，是带时间戳的原话。
  （摘要式的记忆条看起来清爽，但你再也答不了"我当时为什么改变主意"。）
- **不自动改你的记忆**。机器推断出来的东西只标"推断"，**永远不能覆盖你亲手确认过的记录**；
  两者冲突时并排放着，等你裁决。
  （自动合并同一条目的工具，错的时候是静默的——你只会在某天发现"它记错了"。）
- **不做通用 AI 记忆方案**。它假设使用者是**一个人**、数据在**一台机器**上，不做多租户、不做 SaaS。
  （一旦要服务多用户，所有"谁是主体"的判断都会塌掉。）
- **不内置 transport**。它不连微信/QQ/Telegram；那些属于运行时，pmem 只被调用。
  （内置 transport 意味着你换个渠道就要改核心。）
- **不预留插件接口**。两条命令（`context` / `note`）就是最小公约数，会调命令行的都是合法接入方。
  （"先留个扩展点"通常意味着先猜错一次。）
- **不做云端同步**。数据库是本地明文文件，备份自己负责。

## 术语（正文里出现过的几个自造词）

| 词 | 在这里是什么意思 |
|---|---|
| **热记忆 / 冷记忆** | 当前"这段还醒着"的对话整段注入给模型；其余才是可检索的历史 |
| **清醒段 / 转冷** | 一段连续的对话。睡了一觉（间隔够长且落在你的睡眠时段）就"转冷"，上一段结束、新的开始 |
| **证据门** | 检索之后、作答之前的一道检查：这些证据够不够回答？不够就先反问，别硬编 |
| **标签闭集** | 标签的值只能从你审核过的词表里选；模型自创的值进"待审"，不参与检索 |
| **推断 / 已确认** | 机器看原文猜出来的（可能错，可被推翻）vs 你亲手确认过的（机器不许改） |
| **待裁决** | 机器判断不了、只能你来定的问题，比如"半年前那个老板和昨天那个是不是同一人" |

## 一次提问里发生了什么

以"我上次说手冲咖啡定的什么参数"为例，pmem 会依次做四件事（每件都可能不调用模型）：

| 步骤 | 做什么 | 花不花钱 |
|---|---|---|
| 1 算边界 | 算出现在这段对话从哪开始（热记忆边界） | 不花 |
| 2 路由 | 判断"要不要回头查历史"，并抽出关键词 | 一次调用（有规则兜底） |
| 3 检索 | 标签主路径 + 全文兜底，然后在 SQL 层排除热窗段 | 不花 |
| 4 证据门 | 命中的片段够不够回答？不够就转成"反问细节" | 一次调用 |

够了才生成。所以**一次带检索的回答 ≈ 3 次模型调用**；闲聊通常只有 1 次。

## 命令

|---|---|
| `init` / `stats` / `verify` | 建库 / 统计 / 自检 |
| `import takeout\|voyager <zip>` | 导入外部对话（`--dry-run` 只看清单） |

| `ask "<一句话>"` / `chat` | 单次问答 / 交互对话 |
| `context "<这句话>"` / `note "<一条消息>"` | 给运行时的两个出口：算上下文 / 写消息（时间由 pmem 盖章） |
| `tag run\|rerun\|seed\|propose\|add\|list\|approve\|reject` | 打标与词表维护 |
| `daily [--now]` | 补跑闲时整理（正常会自动跑；这条给定时任务或手动补） |
| `review weekly\|monthly` | 周度矛盾 / 月度漂移（只记录，不催改） |
| `pending list\|answer\|propose\|apply\|reject\|log` | 待裁决：看 / 回答 / 让系统提一条动作 / 确认执行 / 看审计 |
| `entity sync\|list\|show\|tenure\|candidates\|ask` | 实体与归属区间（只给候选，不下结论） |
| `profile add\|list\|confirm\|history\|export` | 用户状态：一条说法 + 有效期 + 原文证据（可导出 md） |
| `describe` / `sleep` / `gaps` / `attach` / `export` / `purge` | 图片描述 / 手动睡眠点 / 导入缺口 / 补附件 / 导出 / 彻底清除 |

## 验收

```bat
python tools/run_all.py
```

**96 项行为断言**，一条命令跑完。它会校验每项实际跑出的条数——少一条、多一条都算失败，
所以"把断言删掉让测试变绿"这条路是堵死的。

（空库上会有 2 项跳过：没有探针词、没有附件可验。那不算失败，只是没数据。）

这些不是覆盖率，是**不变量**：不重不漏、派生不覆盖确认、反向对照（证明测试不是空测）、
词汇鸿沟、睡眠窗口边界、离线不写假描述、提议不动数据……

## 人设（让它像个人说话）

默认语气是克制的"记忆助手"。想让它像个人，写一份人设：

```bat
copy persona.example.md persona.md   :: 照着改
```

`persona.md` 只影响**怎么说话**，不改它记不记得住。文件里可以写称呼、语气、你讨厌的腔调
（比如"不要复述我的问题"），它会被放在系统提示词最前面。

有一点边界：人设**不能覆盖记忆规则**——写"你什么都知道"也不会生效，
没有记录时它仍然会说没有记录。

## 已知限制

1. **Takeout 不含助手回复**（少数例外）。历史数据里助手侧基本缺失。
2. **部分附件只有引用没有文件**（生成类图片）。这些记为"导入缺口"，可用 `attach` 手工补。
3. **图片描述需要视觉模型**；没有就留空，不会编造。未描述的图对模型"不可见"——热窗会明说"你看不到，不要猜"。
4. **机器只给候选，不下结论**：待裁决、实体同一性这类问题，最终由你定。
5. **只有 Windows 启动脚本**（`run.cmd`）；Linux/macOS 用 `python -m pmem <命令>`。
